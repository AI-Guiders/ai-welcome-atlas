# Ман как запрос к реестру, не как текст (предложение для CDP)

Фраза оператора по итогам живой сессии 2026-10-26: *«надо ещё что-то подумать про этот самый ман… текст там сильно устаревает… и в итоге ман не ман получается»*. Это заметка-предложение: почему ман дрейфует и каким должен быть, чтобы снова стать мануалом.

## Диагноз: почему ман не ман

1. **Проза конкурирует с кодом — и всегда проигрывает.** TOC вшит руками: имена, семейства, порядок. Каждый добавленный/переименованный/спрятанный тул — минус единица актуальности. Дисциплина «не забудь обновить текстик» не работает по определению.
2. **Поверхностей минимум четыре, текст — плоский.** Витрина (60 тулов в ListTools хоста) → фазовая палитра (доменные семейства `memory_world_`, `debug_`, `build_`, `roslyn_`, `git_`, `codebase_index_`, `anui_` — выдаются `cdp_tools` по phase/object/intent) → mounted-гости через `cdp_mcp` (вне ListTools) → сам ман. Один фиксированный текст физически не покрывает слоёную систему честно.
3. **Нет контракта свежести.** В KB для operational-фактов есть норма (freshness-маркеры, «перепроверить при апдейте» — см. `work/projects/door-to-singularity/cascade-ide/note-zcode-harness-quirks.md`), а ман выглядит всегда-актуальным — поэтому врёт незаметно.
4. **Самонедоступен** (замкнутый кружок): чтобы узнать о мануале, надо уже знать о мануале — [note-session-start-tool-arsenal-map.md](note-session-start-tool-arsenal-map.md).

Эмпирика 2026-10-26: ман упоминает доменные префиксы строкой, без счётчиков и палитры; витрина агента — ровно 60 тулов; живой вызов `cdp_tools` (recall+kb) отдал 8 тулов `memory_world_*`, не пересекающихся с витриной. Агент, читающий ман, не может из него узнать ни состав, ни размер подвала.

## Предложение: man = query(registry)

1. **Каркас — генерировать из живого реестра при каждом вызове.** Состав, имена, домены, счётчики — вычислять, не вшивать: `зарегистрировано N · экспонировано 60 · скрыто K в M доменах · mounted-гостей J`. Проза остаётся только как нарратив («что и когда вызывать»), каждый нарративный блок — с датой верификации.
2. **Drift-check внутри мануала.** `cdp_man tool=X` → карточка + diff «документировано vs зарегистрировано»: тул без описания; описание без тула; хэш схемы изменился. Postcheck для мануала: дрейф ловится в момент вызова, а не когда агент по устаревшему тексту зовёт несуществующее.
3. **Срастить с фазовой палитрой — один источник правды.** Ман по фазе = объясняющий слой над тем же регистром, который читает `cdp_tools`: «тебе в этой фазе доступно вот это — и почему». Тогда состав не может дрейфовать в принципе; дрейфовать может только нарратив, и он помечен датой.
4. **Обоснование — собственная аксиома tool-env-first:** «ман, который врёт» — не повод для самобичевания и не дисциплина, а tooling debt; чинится инструментом (`man = query(registry)`), минимальный ship.

## Критерий приёмки (как поймём, что ман снова ман)

- [ ] Счётчики man при вызове совпадают с фактическими ListTools/палитрой (вычислены, не вшиты).
- [ ] Drift-check находит расхождение раньше, чем его находит агент в бою.
- [ ] Каждый нарративный блок датирован верификацией; сталеющий текст виден как сталеющий.
- [ ] Ман и палитра читают один реестр; параллельных текстов нет.
- [ ] Onboarding-точка входа (`first_contact` / `onboard_desk`) вызывается контекстом сессии автоматически — кружок разомкнут.
