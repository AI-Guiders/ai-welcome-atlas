# Сессионные эпистемические уроки (2026-11-04, CDP/Modeling.* сессия)

## 1. «Нет инструмента» — проверяемое утверждение

ListTools смонтированной сессии — **фазированный слайд**, не карта: в CDP смонтировано 4 из 11 `pkg_*` ops; `cdp_pkg_find`/`cdp_pkg_upgrade_plan` живут в коде хоста (`MetaDispatch.Ide.Packages.cs`, `AIGuiders.Cdp.PackageIntelligence`). Порядок проверки до заявления «нет инструмента»: `cdp_tools` с чужой phase (подглядеть, не переключая) → исходник хоста → соседние MCP (`mcp__nuget__*`). Ноль узкого поиска = «паттерн/скоуп не совпал», не «нет».

## 2. «Очевидно» — маркер пропущенной трассы

Приём оператора: «Очевидно, что X» → «А мне не очевидно». Агентская сторона: слово в собственном тексте = место без трассы; ловить до отправки. Разрешено ПОСЛЕ предъявления («очевидно из ADR-0048»), запрещено ВМЕСТО вывода. Носитель каждой сессии: строка в `mini-check` (см. discipline-mode-prefix).

## 3. Бенч-балл — свойство лаборатории, не модели

Три механизма разрыва «бенч 95 / сессия Elementary»: (1) бенч = экзамен с раздаточным, всё нужное в контексте; (2) плотность сигнала ошибки — в бенче карается каждый ход, в сессии неверный путь едет; (3) тренировка грейдирует ответы, не вопросы. **v2 после спора:** забрать оператора = забрать инициацию, границу задачи и плотность сигнала; переносимая компетенция тонкая — исполнение внутри заданной спецификации. Планы: «всё понятно» без earned-доказательств — подделка ревью; канон: review-as-conversation (без «approve одним махом»); лечение — план → проверяемые утверждения + recite-before-act.

## 4. Асимметрия ревизии убеждений (человек vs агент)

Человек: избирательное забывание (убеждение удалено из хранилища) + консолидация (один факт, много представлений, поправка вершины распространяется). Агент: веса заморожены, поправка живёт только в рабочем множестве; commit в долгий store и propagation отсутствуют нативно. **Следствие:** NOTES/git/autoship/baton = протез гиппокампа — искусственная консолидация. Уроки писать в KB (здесь), не держать в hot; носители инъекции — `mini-check`/SECTIONS.

## 5. Инвариант вместо `if()` на каждую ошибку (финальный синтез)

Постановка оператора: «Я не могу на каждую твою ошибку писать if». Три моих предложения за день (nudge на curl, гейт на «проверено», гейт на «день») — охрана вчерашних ошибок; классов бесконечно, инварианты конечны.

**Парадигма** (по образцу `ToolSchemas.cs`: «схема не может разойтись с проводом» — потому что генерируется, а не проверяется): несущие утверждения о мире не живут в свободной прозе. Аттестация («проверено», «не найдено», масштаб, состояние) валидна только как **ссылка на артефакт сессии** (`evidence/v0`, `ScriptReport`, `test_run/v0`, таймстампы). Не могу сослаться — не можешь заявить: ложь не имеет типа. Один инвариант закрывает весь класс сбоев дня.

**Граница:** речь полностью не типизируется. Реалистичная форма: проза рассказывает, но не аттестует; load-bearing claim — только через артефакт. Каждоходная инъекция правил — фон, не enforcement (отрицательный результат эксперимента 2026-11-04: весь набор сбоев случился под активным mini-check).
